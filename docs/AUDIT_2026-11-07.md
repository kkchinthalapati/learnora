# Learnora audit — 2026-11-07

Production: `https://learnora-app.vercel.app/app/`, using the signed-in test account in the in-app browser.
Repo: branch `daily-return` at `8202bbf`, plus a large uncommitted working tree (see A-1).
This is a **partial** audit. §13 lists what was tested and what wasn't. Nothing here says a feature passes unless it was exercised.

---

## 1. Executive summary

The core loop works on production. I typed a topic and got notes and an outline, worked a Learn lesson (guess → explanation → check → re-teach on a miss), resumed after a refresh, asked the tutor, and reviewed cards. Security is in good shape: RLS is on for every public table, storage is scoped per user, and every `SECURITY DEFINER` RPC checks `auth.uid()`.

The serious problems are about **coherence**, not crashes:

1. **Lessons are stuck where they were created** (P1, F-01). Home creates topic lessons with no subject. No screen lets a student move, rename or delete a single lesson (`removeMaterial` exists but nothing calls it). The lesson's *Mistakes* tab tells the student to "Put this lesson in a subject", which they can't do. Most lessons on the test account are "No subject", so the misconception ledger is invisible from those lessons.
2. **Raw `<openui>` tags show in tutor replies** (P2, F-02). Generated notes also show "Some of this card couldn't be drawn" twice in one note (F-03).
3. **Two open PRs conflict with each other and with unpushed local work** (§9). The `daily-return` working tree also holds about 50 uncommitted files of unrelated feature work, and that's where the only test and typecheck failures are.
4. **Plan, Library, Notebooks, Mark-my-answer and Exam traps are missing from the main navigation** (F-07). You reach them only through Search, Help, or links inside pages.

## 5. UX / UI review (observed)

- **Learn is the strongest surface.** The order (big picture → guess → teach → check → re-teach) is clear, the stage label ("PART 1 OF 3 · … · CHECK") anchors the student, and resume works. Weaknesses: the 15–20 s first wait shows only a sentence (no outline or skeleton), and the repetition in F-15 makes each part longer than it needs to be.
- **Lesson tabs (6) plus "Start session"** compete with each other. At 375 px, "Tutor" and "Mistakes" sit off-screen in a scroll strip with no sign there's more. Mistakes, the product's differentiator, is the most hidden tab.
- **Fix these** on Home is a good idea, but its items ("Gap in the idea: Lee v Lee's Air Farming Ltd") come from several subjects with no subject label.
- **Test-data pollution is visible to the test account:** `.gpx` and `this_is_not_pdf` uploads and three "image · Notes didn't finish" rows sit in Home's lesson list. A real student who hits failures sees the same: failed rows stay forever because there's no delete (F-01).
- **Accessibility spot checks passed:** the h1 typewriter has an `aria-label` and an `aria-hidden` animation, bottom tabs have text, there's a skip link, and the flashcard back is `aria-hidden`. Minor: bottom tabs don't set `aria-current` (the top nav does). Not done: a full keyboard pass, a contrast audit, or an axe run against production (CSP would block injecting it; run `@axe-core/playwright` from `webapp/tests` instead).

## 6. Architecture review

- **Three creation surfaces for one action:** the Home composer (`CaptureBar`), the `/capture` page (orphaned, no links), and the header pencil / `MaterialPanel`. Make `CaptureBar` the single implementation. `/capture` can redirect to `/`.
- **Two organisation hierarchies:** the `Subjects` page and `Library ▸ Subjects` list the same folders through different views. Library adds the lesson, card-set, quiz and notebook lists. Recommendation: one "Subjects" area with the Library tabs inside it, rather than two entry points.
- **Billing logic is duplicated client and server** (`webapp/src/api/aiUsage.ts` mirrors `billingDecision`). Both PR #165 and local commit `5e309f8` edit this mirror differently (§9). Generate the client rule from the shared `sessionBilling.js` or have the server return used units, so the two can't drift.
- **Uncommitted WIP on a PR branch.** `daily-return` has 30 modified and about 20 untracked files (learner style picker, podcast, cookie banner, `GenerationProvider`, chat sources) that are unrelated to PR #166. All current tsc and Vitest failures are in those files. Move them to their own branch before anything else is pushed from this checkout.
- Lint: `oxlint` has 0 errors, with warnings including a `useMemo` dep on `handleClose` that changes every render (`webapp/src/components/command/CommandPalette.tsx:612`).

## 7. Security review

**Confirmed from production metadata (read-only SQL and advisors):**
- RLS is enabled on every `public` table. Five tables have RLS and no policies (`ai_item_cache`, `email_notification_log`, `push_notification_log`, `question_review_log`, `stripe_events`), which means service-role only. That's correct for logs.
- Only `question_bank` and `question_flags` are readable by every signed-in user (`using (true)`). That's intended shared content.
- Storage: `materials`, `card-media` and `chat-media` are scoped to the `auth.uid()` folder for every command they allow. `avatars` is public-read, which is intended.
- The 7 `SECURITY DEFINER` friend RPCs all reject a null `auth.uid()`, pin `search_path`, and `resolve_friend_code` validates the code's shape. Advisor WARNs are expected for this design.

**Open items (owner settings, not code):**
- **Leaked-password protection is off** in Supabase Auth. Turn it on (Auth ▸ Password security).
- `pg_net` is in `public`. Low risk; move it when convenient.

**Not done:** an edge-function code review for prompt injection or auth checks, a cross-account access test (no second account, by rule), and a dependency vulnerability scan (`npm audit`).

## 10. Integration recommendations

1. **Make the misconception ledger reachable from every lesson** (F-01). It's the differentiator, and today a no-subject lesson hides it. Either subjects become optional for mistakes, or lessons can be filed.
2. **One organisation area.** Merge `Library` into `Subjects` (lessons, card sets, quizzes, notebooks as tabs), and give every row Open / Move / Rename / Delete.
3. **One creation entry.** `CaptureBar` everywhere; retire `/capture`.
4. **Surface Plan.** Exams drive `/study`'s recommendations ("from your mistakes and your next exam"), yet Plan, where exams are entered, is hidden (F-07).
